ThreadPilot — setup and how to run it

The General Manager's Co-Pilot for a quick-response knitwear factory: morning briefing, questions over the order and production records, alerts, feasibility checks and confirmed actions. Public code: github.com/jingweiluo557/DSS5105 (folder threadpilot/). Live demo: threadpilot-dss5105-track1-i7gxvcy5k7ef5ac9b.webapps.tcloudbase.com (the workspace access key is shared with the teaching team separately; it is never committed).

2. Requirements

  • Python 3.11–3.13 and uv (or pip). Dependencies are pinned in backend/pyproject.toml / uv.lock: FastAPI, SQLAlchemy 2, Pydantic 2, the OpenAI SDK, LangChain-OpenAI (SQL assistant only), Alembic, msal/httpx (Outlook).
  • Database: SQLite is enough to run everything locally; MySQL 8 is the shared deployment database.
  • A language-model key (OPENAI_API_KEY, any OpenAI-compatible endpoint via OPENAI_BASE_URL) for the chat planner/narrator, the morning briefing and voice transcription. Without a key the server still answers through the keyword planner and every tool, briefing and alert rule works; only the wording is plainer.
  • Node 18+ only for the browser tests and the demo recorder (Playwright + Chromium) and ffmpeg for the video assembly. Not needed to run the app.
  • Optional: a Microsoft Entra app registration to send chase-ups and alert emails from the manager's own Outlook (see docs/OUTLOOK.md).

3. Run it locally

3a. The fastest way: offline replay (no keys, no database, 30 seconds)

The real frontend and the real workflow engine over the CSV files, with a scripted planner standing in for the model. Every tool, the queue simulation, the alert policy, the home screen and the dialogue rules are real; nothing is sent.

git clone https://github.com/jingweiluo557/DSS5105.git
cd DSS5105/threadpilot
uv sync --project backend --frozen          # or: pip install -e backend
backend/.venv/bin/python demo/replay_server.py 8765
# open http://127.0.0.1:8765/index.html  — business date 1 April 2026

3b. The full application with a model key (SQLite)

cd DSS5105/threadpilot
uv sync --project backend --frozen
cp backend/.env.example backend/.env
# edit backend/.env — the minimum:
#   OPENAI_API_KEY=…            OPENAI_MODEL=gpt-6-luna      (or any chat model with JSON output)
#   DATABASE_URL=sqlite:///./runtime/business.sqlite3
#   AI_DATABASE_URL=sqlite:///./runtime/business.sqlite3
#   BUSINESS_NOW=2026-04-01T12:00:00+08:00   (dataset replay clock; use "live" for real operation)
cd backend
uv run python -m scripts.init_db --seed-existing     # creates the schema and imports the three CSVs
uv run python -m scripts.serve                       # http://127.0.0.1:8000

Then open the address, enter the workspace access key you set as API_ACCESS_TOKEN (any string locally), and start with the home screen. The 07:00 briefing is written when you press "Write it now" or when the business clock passes 07:00 (Settings → Business clock → Start demo clock).

3c. MySQL and Docker

cp .env.example .env            # root of threadpilot/: set the passwords and tokens
docker compose up --build -d    # provisions MySQL, migrates, starts the backend on :8000
docker compose exec backend python -m scripts.init_db --seed-existing --skip-migrate

For a hand-provisioned MySQL: set MYSQL_ROOT_PASSWORD, run python -m scripts.provision_mysql, then the two commands of 3b. Never seed an existing production database; schema changes go through python -m scripts.upgrade_cloud_schema --apply.

4. Tests and the evaluation

cd threadpilot/backend && uv run pytest -q                      # regression tests, SQLite, no model key
cd ../evaluation
../backend/.venv/bin/python build_eval_set.py --out /tmp/eval_set.json   # recomputes every gold answer from the CSVs
../backend/.venv/bin/python run_annotated_eval.py --out /tmp/t.json      # the 88 questions through the server, planner annotated
../backend/.venv/bin/python score.py --eval eval_set.json --transcript /tmp/t.json --out /tmp/r.json --report /tmp/REPORT.md --strict
# live, against a running backend with a model key (writes a dated transcript; never overwrite a first pass):
THREADPILOT_URL=http://127.0.0.1:8000 THREADPILOT_ACCESS_KEY=… ../backend/.venv/bin/python run_live_eval.py --out transcript_live_$(date +%Y%m%d).json

# held-out ground truth (70 questions written from the data files only; Sprint 3)
cd heldout
../../backend/.venv/bin/python gold/build.py            # recomputes the gold twice (Python and SQLite) and refuses to write unless both agree
../../backend/.venv/bin/python run_heldout.py ideal      # 48/70 with the planner's reading supplied; results/heldout_ideal.json
../../backend/.venv/bin/python run_heldout.py fallback   # 15/70 with no language model
THREADPILOT_TOKEN=… ../../backend/.venv/bin/python run_live_heldout.py --base https://<backend>   # the same 70 on the deployed model

# the team's two 300-turn question sheets (100 questions × 3 phrasings each)
cd ../q100
../../backend/.venv/bin/python run_q100.py ideal && ../../backend/.venv/bin/python grade.py answers_ideal.json
Q100_SET=similar ../../backend/.venv/bin/python run_q100.py ideal && ../../backend/.venv/bin/python grade_similar.py answers_similar_ideal.json

Keys such as THREADPILOT_TOKEN are read from your own shell only; never put them in a committed file.

The GitHub workflow threadpilot-backend.yml runs the tests and the offline evaluation on every push; demo-video.yml records the demo on the offline replay and assembles the presentation video (Sprint 3 timeline: demo/demo_timeline_sprint3.json).

5. Configuration that matters

VariableMeaning
OPENAI_API_KEY, OPENAI_MODEL, OPENAI_BASE_URLThe planner / narrator model. INTENT_API_STYLE=chat_completions for providers without the Responses API. TRANSCRIBE_MODEL (default whisper-1) for voice when the browser has no speech recognition.
DATABASE_URL, AI_DATABASE_URLApplication and read-only (SQL assistant) connections. WORKFLOW_STORAGE=database keeps chat state, drafts, reminders and the alert ledger in MySQL instead of local SQLite.
BUSINESS_NOWThe business clock for dataset replay (2026-04-01T12:00:00+08:00) or live. Settings can advance a demo clock.
API_ACCESS_TOKEN, SCHEDULER_TOKEN, CORS_ORIGINSThe workspace access key the browser asks for; the token the minute timer uses; allowed frontend origins.
OUTLOOK_CLIENT_ID, OUTLOOK_CLIENT_SECRET, OUTLOOK_ENCRYPTION_KEY, OUTLOOK_REDIRECT_URISending from the manager's own mailbox. The encryption key must be kept across releases.
ALERT_EMAILS_ENABLEDDeployment-level switch for alert emails (default false). The manager's own switch in Settings has the same effect.
