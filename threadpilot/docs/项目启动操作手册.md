# ThreadPilot 项目启动操作手册（展示用）

适合现场演示前使用。以当前 Windows 项目目录为例：`D:\GitProjects\DSS5105\threadpilot`。如果项目放在别处，请替换路径。

本手册按“本机已完成配置”的情况启动，不会重新导入或清空数据库。展示内容见 [用于展示的测试方法](用于展示的测试方法.md)。

## 1. 展示前准备好这三个窗口

| 窗口 | 用途 |
|---|---|
| PowerShell | 启动后端；演示期间保持打开 |
| 浏览器 | 展示页面和 AI 对话 |
| DataGrip | 查看 MySQL 数据、演示数据更新 |

本机应已有 Python 3.12/3.13、uv、MySQL，项目的 `backend/.env` 已配置数据库和模型。模型请求需要网络和可用额度。

首次部署尚未完成时，先按 [项目 README 第 6、7 节](../README.md#6-环境准备) 安装依赖、配置账号、迁移和导入，再使用本手册。不要为了开始演示重复初始化已有数据库。

## 2. 确认 MySQL 正在运行

打开 PowerShell，执行：

```powershell
Get-Service *mysql*
```

看到 `Running` 即可。如果是 `Stopped`，打开 Windows“服务”，找到实际的 MySQL 服务并启动。部分电脑的服务名是 MySQL80，以本机为准。

## 3. 启动项目

### 推荐：使用历史数据演示日期

目前种子生产数据截止到 2026-03-31。固定到次日演示，“昨天的产出”和“今天的订单”更容易理解。

在 PowerShell **逐行执行**：

```powershell
cd D:\GitProjects\DSS5105\threadpilot
$env:BUSINESS_NOW = '2026-04-01T09:00:00+08:00'
$env:SYNC_ENABLED = 'false'
./backend/start.ps1
```

这里的设置只影响当前 PowerShell 启动的进程，不改写 `.env`。暂停文件同步是为了让 DataGrip 的现场修改保持可观察，避免另一条数据更新链路同时运行。

看到以下信息表示后端启动完成：

```text
Application startup complete.
Uvicorn running on http://127.0.0.1:8000
```

**不要关闭这个窗口。** 如果已有服务占用 8000，应在原服务窗口按 `Ctrl+C`，再用上述设置启动。已有服务不会自动采用新终端的日期设置。

如果 PowerShell 阻止运行 `.ps1`，可在同一窗口改用：

```powershell
cd D:\GitProjects\DSS5105\threadpilot\backend
uv run --locked uvicorn app.main:app --host 127.0.0.1 --port 8000 --workers 1
```

### 使用当前真实日期时

把启动前的日期设置改成：

```powershell
$env:BUSINESS_NOW = 'live'
```

之后重新启动后端。旧订单可能全部逾期，“昨天”也可能没有产出数据；这是数据日期与当前日期不同造成的。下份测试手册的固定数值以 **2026-04-01 演示日期、未改动种子数据** 为前提。

## 4. 打开页面并做三项检查

1. 打开 [项目首页](http://127.0.0.1:8000)。不要双击 `frontend/index.html`。
2. 进入 Dashboard，确认能看到订单数量和图表，业务日期为 `2026-04-01`。
3. 进入 AI workspace，输入 `Open order ORD-005.`，收到回答后打开右侧证据链接。

也可以直接访问：

| 地址 | 正常现象 |
|---|---|
| [健康检查](http://127.0.0.1:8000/api/v1/health) | `status` 为 `ok`，`configured` 为 `true` |
| [数据库快照](http://127.0.0.1:8000/api/snapshot) | 包含 orders、production_log、workshops 和 today |
| [AI 工作台](http://127.0.0.1:8000/#/ai) | 能输入问题并获得真实回答 |
| [API 文档](http://127.0.0.1:8000/docs) | 可查看和试用接口 |

`configured: true` 只说明读取到了模型配置。实际发送一个问题成功，才能确认模型调用可用。

## 5. 在 DataGrip 中连接同一数据库

1. 新建 MySQL 数据源；已有连接时直接使用。
2. 按 `backend/.env` 中 `DATABASE_URL` 的主机、端口、库名、账号配置连接。不要把完整连接串或密码放进演示截图。
3. 修改数据需要有 UPDATE 权限的应用／演示账号；不要使用 `AI_DATABASE_URL` 的只读账号。
4. 点击 Test Connection，成功后打开该连接的 Query Console。
5. 执行以下只读查询：

```sql
SELECT DATABASE() AS current_database;
SELECT COUNT(*) AS orders_count FROM orders;
SELECT COUNT(*) AS production_count FROM production_log;
SELECT COUNT(*) AS workshops_count FROM workshops;

SELECT id, order_id, customer, product, pieces, current_stage,
       last_activity_date, version
FROM orders
WHERE order_id = 'ORD-005';
```

初始种子通常是 120 / 360 / 8，实际以当前数据库为准。如果控制台没有选择数据库，请在 DataGrip 中选择 `DATABASE_URL` 对应的 schema 后再执行。

**记住：数据库修改必须提交，AI 才能看到。** 下份手册使用显式 `START TRANSACTION` 和 `COMMIT`；不要只修改表格单元格而忘记提交。

## 6. 演示前最后检查

- [ ] 浏览器和 DataGrip 指向同一个本地后端／数据库。
- [ ] Dashboard 业务日期为 2026-04-01。
- [ ] ORD-005 查询和数据库证据链接正常。
- [ ] AI workspace、Activity Log、Settings 都能从侧边栏进入。
- [ ] 已准备 DataGrip 数据备份，知道如何恢复。
- [ ] 如果展示真实发送，已配置专用测试收件人和发送网关；否则只展示草稿与未配置提示。
- [ ] 演示屏幕不显示 `.env`、密码或管理令牌。

演示过程中不点击 Reset local actions & preferences，以免清掉要展示的本地记录。

## 7. 常见问题快速处理

| 问题 | 处理方法 |
|---|---|
| 页面打不开 | 看启动窗口是否仍在运行，确认地址和端口 |
| 8000 被占用 | 先停止原来的项目服务，不要重复启动 |
| 页面提示数据库不可用 | 检查 MySQL 服务、DATABASE_URL 和迁移是否完成 |
| 模型返回 502 / MODEL_API_ERROR | 检查网络、模型地址、密钥权限；页面正常不代表模型服务可达 |
| 模型返回 429 | 等待上游限流恢复或检查额度，避免连续重试 |
| 修改数据后看板没变 | DataGrip 提交后刷新浏览器；看板不是自动实时推送 |
| 聊天没看到新值 | 检查是否 COMMIT、是否连错库，再说“Refresh order ORD-005.” |
| 日报与准备的数字不同 | 检查业务日期、数据库是否被修改，以及问题选择的时间范围 |
| 新终端设置日期后页面没变化 | 需要停止旧后端，再从设置了日期的终端启动 |

## 8. 展示结束

1. 按测试手册恢复修改过的 MySQL 字段并提交。
2. 刷新页面，确认恢复结果。
3. 在后端窗口按 `Ctrl+C` 停止服务。
4. 如果继续日常使用，在启动前设置 `BUSINESS_NOW=live`；要恢复 `.env` 中的同步配置，可在同一终端执行：

```powershell
Remove-Item Env:BUSINESS_NOW -ErrorAction SilentlyContinue
Remove-Item Env:SYNC_ENABLED -ErrorAction SilentlyContinue
```

移除后下次启动使用 `.env` 中的配置。测试中保存的聊天、内部备注和提醒属于服务端 SQLite 数据，恢复 MySQL 或重置浏览器不会删除这些记录。
