# 订单管理记录

**目的**：经理在聊天中确认一次，就能在工作区总览和对应订单详情看到同一条记录。浏览器不需要保持打开。业务时间采用工厂时钟（UTC+8）。

| 请求 | 确认预览 | 确认后 |
| --- | --- | --- |
| 给 ORD-005 备注下，客户需求量有变化。 | 明确订单号并回显备注原意。 | 保存内部备注。数量字段和生产状态不变，不安排定时检查。 |
| 如果今天 ORD-005 状态没更新，明天的晨报告诉我。 | 列出订单、观察日期、检查字段、目标晨报日期。 | 登记一次性跟进。截止后检查该业务日内是否发生订单状态或生产阶段变化。 |

## 操作与可见性

- 聊天沿用经理确认、预览过期、订单快照核对与重复确认保护。订单不明确时先澄清。
- AI workspace → Watches & receipts → Management records 查看共享总览。订单页 Management notes 展示备注，Related follow-ups 展示条件跟进。Add note 的 Save note 与聊天确认使用同一后端记录服务。
- 刷新或更换浏览器后，具有该工作区读取权限的用户可看到同一组记录。旧的浏览器本地备注仅在原浏览器订单页保留，模拟邮件回执仍单独展示。
- 现有共享数据库里的工作流 note 直接出现在记录列表。新的共享备注不依赖聊天会话的生命周期。

## 检查、归档与投递

观察窗口为指定业务日零点至次日零点。订单 API 和项目导入器在写入订单的同一事务中保存状态/阶段变化事件。修改数量、写备注以及给订单发邮件均不算状态变化。日内变更后又恢复原值仍算变化。直接绕过项目写入数据库的操作不在监控范围内。

检查结果保存在原跟进记录。当天有变化，标为 changed，不加入晨报。完成整日观察且没有变化，标为 no_change。历史覆盖不足或订单当天新建、删除导致无法证明整日无变化时，标为 unverified，晨报注明原因。首次启用当天历史不能回填。现有云端分钟定时器和提醒检查入口可自动检查，本地后台检查也受现有配置控制。

晨报生成和回写报告关联在同一事务内完成。命中的记录以确定性文本加入「Manager follow-ups」，不要求语言模型重新判断。若启用了工作区邮件投递，它也会出现在晨报邮件中。云端分钟定时器会在目标日 07:00 后为待入报的记录请求生成站内晨报，邮件开关独立。报告生成失败仍保留已检查的记录，可在目标日重试。整天停机而错过目标日报时，跟进结果保留在记录页，不冒充已归档或已送达。
