# 对话升级与验收

本次根据用户提供的测试表补齐：订单总数、按工序/状态统计、客户累计件数和订单笔数；新增订单的数量、产品和工作日交期在追问期间保留；通用回答不再绑定当前订单。

## 实现方式

`ConversationAgent` 先用结构化计划拆分最多六个要求，随后由服务端调用既有业务路由。统计工具从当前数据库读取并计算，风险概览使用与插队相同的 QueueAnalysis。模型没有任意 SQL、任意网络或直接调整排程的权限。另一轮模型调用依据工具结果组织回答，使用 Responses 文本增量事件或 Chat Completions 内容增量直接转发 SSE。

服务器保存最近十六条消息、当前槽位，以及按业务意图保存的主题条件。通用问题与全局统计不覆盖当前业务条件；明确恢复其他业务主题时恢复其订单和槽位。该版本保存的是有限主题记忆，不是无限历史检索。同一意图的历史主题只保存最近一份。

文本流开始前会先识别要求、获取数据；不是从请求发出瞬间就有文字。模型返回片段后立即显示，不用完成后的答案模拟打字。生成中断不保存半段回答。客户端断开会取消生成，服务器清理任务和模型连接。

审核候选草稿、执行预览、晨报原文仍按原服务输出，避免再次改写已确认内容。这些业务步骤可能等待其结果完成；一般回答和工具解释使用真正的模型流。最终审核和排程仍在表单确认。

模型缺失或失败时回退为标明“基础回答”的本地结果；可识别的统计、明确订单查询、风险或插队仍可使用。基础识别仅覆盖常见表达，不具备模型的通用理解能力。已输出一部分后发生异常会显示失败，不把模板拼接成貌似完整的模型回答。

## 确认与数据边界

多个查询可以一起处理；多个执行动作需分别预览确认。切换或继续对话保留草稿，但撤销旧执行确认，需请求新预览。数据库写入、审核草稿版本检查、手工编辑保护和确认 ID 规则保持不变。

工作日沿用当前业务口径：周一至周六，不含未配置的节假日。新订单承诺评估仍用既有保守产能工具，不代表确定交付承诺。风险等级不是延误概率。通用回答没有联网搜索功能。

## 验证

- 原业务及新增隔离回归：119 项通过，MySQL 集成 1 项因未配置而跳过。
- 浏览器验证：完成前显示文本、停止、重试、新会话隔离。
- 经用户单独授权，使用 api.openai.com 的实际配置验证七轮连续对话：具体工序、统计、多要求、客户件数/笔数、插入通用话题后恢复新订单条件、风险时间窗口。
- 额外实测两张订单加通用概念的一次请求，修复子任务订单范围后，分别调用两次查询；本地 HTTP 收到 78 个文本增量，首段约 6.44 秒，完成约 6.92 秒（单次测试，不是性能承诺）。
- 验收库业务日期为 2026-04-01；数据为独立本地副本，测试未发送催办或调整排程。
