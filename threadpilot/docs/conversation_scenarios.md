# Conversation scenarios

What the Morning Briefing chat does in a real conversation, including the turns that go wrong in a naive assistant: a vague
question, a follow-up that only makes sense after the previous answer, a question the data cannot answer, a request to do
something, and a standing check that fires by itself.

The transcripts below are **recorded, not written**. `scripts/record_scenarios.py` opens `demo/briefing_demo.html` in headless
Chromium on *Thursday 9 April 2026* ("simulated day 8"), asks each scripted question and copies what the chat answered.
`tests/test_scenarios_doc.py` records them again on every test run and fails if this page differs, so the page cannot describe
behaviour the chat no longer has. The chat is the offline one (rules plus the same tools as the live backend), so the
answers are deterministic.

## How this maps to the backend scenarios

The backend (`app/`: the OpenAI intent classifier and the workflow engine) is checked against its own eleven sub-scenarios in
`docs/live_model_verification.md`. The offline chat above answers the same kinds of question with the same tools; the table says
which recorded scenario shows each one.

| Backend sub-scenario | Shown above in |
| --- | --- |
| 1.1 Order lookup | S2, S3 |
| 1.2 Refresh (re-read the data) | every answer reads the day's data again; S7 moves the date |
| 1.3 Risk | S1, S3 ("is it late?") |
| 1.4 Compare | not recorded here; `compare_orders` is described in `docs/tool_spec.md` |
| 1.5 Commitment | S5 (feasibility) |
| 1.6 Prioritise | S1 (the briefing's top five) |
| 2.1 Normality | S9 |
| 2.2 Deviation | S1, S4 ("why did washing drop") |
| 3.1 Chase | S6 |
| 3.2 Note | S6 |
| 3.3 Reminder | S7, S8 |

What has and has not been measured on the **live** backend: the 45-turn batch passed **36 of 45 turns on its first full run**
(7 turns hit HTTP 429 rate limits and 2 lacked a confirmation context because an earlier step had failed). All 45 turns have a
passing record only after re-running the failed ones, not in a single run. The offline transcripts above are not a
measurement of the live OpenAI model.

## What recording these found

Writing the scenarios as a script, rather than as prose, showed that the chat lost the thread in six places. Before the fix,
after "What is the status of ORD-120?":

| Follow-up | Before | Now |
| --- | --- | --- |
| "who is the customer?" | "I can't answer that from this dashboard's data." | "ORD-120 is for TrendCart." |
| "whose order is it?" | same refusal | same answer |
| "which customer?" | same refusal | same answer |
| "how many pieces?" | same refusal | "ORD-120 is 1,500 vest." |
| "is it late?" | "6 orders are late." (the whole factory, not this order) | the status of ORD-120 |
| after "How did packing do yesterday?" and "and washing?": "what about on Monday?" | same refusal | Washing on Monday, 6 April |

The fixes are in `simulation/chat.js`; `tests/test_chat.py` holds one test per fix. A guard test makes sure the new rules cannot
swallow a question about the whole factory ("Which customer has the most late orders?", "How many orders are late?") and that
"Is it late?" with nothing to refer to still asks which order.
